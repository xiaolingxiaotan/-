# M2-2 靶标说明

## 用的就是 M2-1 那块棋盘格

- 方格：**10 列 × 7 行**（横向 10 格、纵向 7 格）
- 内角点：**9 × 6**（横向 9 个、纵向 6 个）
- 方格实测边长：**17.0 mm**（卡尺量，和 M2-1 `camera_calibration.yaml` 里记录的一致）
- 靶标整块棋盘区域：**170 mm × 119 mm**
- 方格纸必须贴在硬纸板上，不能有翘曲；否则 `z=0` 的平面假设不成立。

> M2-1 的 YAML 写的是 `inner_corners: [6, 9]`，这是 OpenCV 的 `(cols, rows)` 参数；
> 对这块横放的板来说，`cols=6` 沿短边（竖直），`rows=9` 沿长边（水平）。
> M2-2 代码读取这个 YAML，但物体系按物理长边/短边来定义，见下面的说明。

## 文件

| 文件 | 用途 |
| :-- | :-- |
| `chessboard_10x7_17mm.svg` | 矢量原图，按 **100%（实际大小）** 打印 |
| `chessboard_preview.png` | 屏幕预览，**不能用来打印**（没有物理尺寸元数据） |

打印时关闭“适应页面 / Fit to page”，选 A4、100%。打印后：

1. 量一下图下方的 **100 mm 标尺**，应该是 100 mm；
2. 量任意一个方格，应该是 **17.0 mm**；
3. 如果实测不是 17.0 mm（打印机缩放、纸张误差），以卡尺实测值为准，运行时加
   `--square-mm <实测值>`，不要改 YAML 里的标定内参。

## 物体系与角点顺序（必须和代码一致）

```
原点：棋盘几何中心（内角点阵列中心，也是整块板的中心）
X 轴：沿长边（10 格方向），从左指向右
Y 轴：沿短边（7 格方向），从下指向上
Z 轴：X × Y，垂直板面，指向相机一侧（右手系）
```

正对相机、标题正立时，一个正放的靶标应输出 `roll≈0, pitch≈0, yaw≈0`。

角点数组顺序（检测器返回的 54 个点）：

- 每 `cols=6` 个点为一组，沿短边从下往上；
- 共 `rows=9` 组，沿长边从左往右；
- 所以首角点 `P0` 是**标题正立时的左下内角**，不是左上角；
- 物体系原点是棋盘中心，`P0` 只是角点顺序的起点。

代码会检查 `P0` 周围四个方格的明暗：这块板的 `P0` 主对角线两侧是深色。若检测器
从相反的角开始返回（SB 经常如此），代码会把整个数组倒序，保证 `P0` 始终跟随同一
块物理角点。`--corner-diag light` 是给“左上角为白格”的其他打印板用的，这块板用
默认 `dark`。

## 180° 歧义

棋盘格本身中心对称，单看图案无法区分“正放”和“转 180°”。这块板是 10×7 格，
黑白格数一奇一偶，角点周围的明暗签名可以区分 180°；代码利用这一点做归一化。
现场仍应让**标题朝上**，这样最稳，也符合角点顺序的说明。
