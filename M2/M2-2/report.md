## 0. 环境与运行

```bash
# 摄像头实时
python3 pose_estimate.py --camera 0 --calib ../M2-1/camera_calibration.yaml

# 单张图片（--show 打开窗口；不加则只保存结果图）
python3 pose_estimate.py --image xxx.png --calib ../M2-1/camera_calibration.yaml --show

# 批量图片 + CSV，便于精度实验
python3 pose_estimate.py --image test_imgs/ \
    --calib ../M2-1/camera_calibration.yaml --headless --csv results/pose_log.csv

# 同一帧带畸变 / 不带畸变对比
python3 pose_estimate.py --image xxx.png \
    --calib ../M2-1/camera_calibration.yaml --compare-distort
```

关键参数：

| 参数 | 作用 |
| :-- | :-- |
| `--calib` | M2-1 标定 YAML，默认 `../M2-1/camera_calibration.yaml` |
| `--camera / --video / --image` | 三选一的数据源 |
| `--square-mm` | 重新量过方格边长时覆盖 YAML；默认读 YAML 的 17.0 mm |
| `--no-distort` | PnP 和画轴都用零畸变，用于对比 |
| `--compare-distort` | 图片模式：同一帧分别带/不带畸变解 PnP，打印差值 |
| `--no-refine` | 关闭 `solvePnPRefineLM` |
| `--corner-diag dark/light` | 首角点主对角线应为深色/浅色；这块板用默认 `dark` |
| `--csv` | 每帧写一行位姿，方便算均值/标准差 |

现场按键：`q` / `Esc` 退出，`s` 保存当前结果图到 `results/`。

## 1. 靶标与内参

### 1.1 靶标规格

| 项 | 值 |
| :-- | :-- |
| 类型 | 棋盘格（chessboard） |
| 方格 | 10 列 × 7 行 |
| 内角点 | 9 × 6（横向 9、纵向 6） |
| 方格实测边长 | **17.0 mm**（卡尺量；和 M2-1 标定记录一致） |
| 棋盘区域 | 170 mm × 119 mm |
| 打印/粘贴 | 贴在硬纸板上，保证平面 |

棋盘格必须用**实际量过的尺寸**。位姿的平移量与方格边长成正比：如果真实边长是
17.0 mm，而代码用 16.0 mm，则所有距离会系统性偏小约 5.9%，角度不受影响。

M2-1 的 YAML 里写的是 `inner_corners: [6, 9]`，这是 OpenCV 的 `(cols, rows)`
参数。对这块横放的板，`cols=6` 沿短边（竖直），`rows=9` 沿长边（水平）。
标定本身只关心“一组共面、等间距的点”，所以这个参数顺序是合法的；M2-2 读取
同一组数，但物体系按物理长边/短边重新定义（见下一节），两者不矛盾。

### 1.2 内参来源

只读取 M2-1 的 `camera_calibration.yaml`：

| 项 | 值 |
| :-- | :-- |
| 分辨率 | 1920 × 1080 |
| fx / fy | 1339.266145 / 1340.719651 px |
| cx / cy | 969.781654 / 523.361085 px |
| 畸变 `[k1 k2 p1 p2 k3]` | `[0.079914, -0.329362, -0.004905, -0.000009, 0.350401]` |

量，不随分辨率缩放。缩放只在“整幅图等比缩放”时严格成立；现场应尽量用标定分辨率。

## 2. 物体系定义

```
              Y（短边，向上）
              ↑
              │
              │        X（长边，向右）
              └────────→
             ╱
            ╱
           Z（垂直板面，指向相机）
```

| 要素 | 定义 |
| :-- | :-- |
| 原点 | 棋盘几何中心（内角点阵列中心，也是整块板中心） |
| X 轴 | 沿**长边**（10 格、9 个内角点的方向），从左侧指向右侧 |
| Y 轴 | 沿**短边**（7 格、6 个内角点的方向），从下侧指向上侧 |
| Z 轴 | `X × Y`，垂直板面，**指向相机一侧**（右手系） |

原点取中心的原因：内角点阵列中心与整块板中心重合。横向 10 格，第一个内角点在
离左边 1 格处，最后一个在离左边 9 格处，中点是 5 格 = 板中心；纵向 7 格同理。
这样 `tvec` 直接就是“靶标中心在相机坐标下的坐标”，现场用卷尺量中心最直观。

正对相机、标题正立时：

```text
物体系 X → 相机 X（右）
物体系 Y → 相机 -Y（上；相机 Y 向下）
物体系 Z → 相机 -Z（指向相机）
```

因此“正对”对应的旋转矩阵是

```text
R0 = diag(1, -1, -1)
```

`cv2.solvePnP` 返回的 `tvec` 是**物体系原点在相机坐标系下的坐标**（不是“相机在
靶标坐标下”）。相机坐标系：X 右、Y 下、Z 沿光轴向前。`tvec.z` 是沿光轴的深度，
`distance = ||tvec||` 是到靶标中心的欧氏距离；画面里显示后者，CSV 两个都给。

### 2.1 角点顺序

检测器返回 54 个点，数组下标

```text
k = j * cols + i,   i = 0..5,  j = 0..8
```

- `i` 方向（每 6 个点一组）沿**短边**，从下往上；
- `j` 方向（共 9 组）沿**长边**，从左往右；
- 首角点 `P0` 是标题正立时的**左下内角**；
- 物体系原点是棋盘中心，`P0` 只是角点顺序的起点，不是原点。

物点按下式生成（米，`z=0`）：

```text
x = (j - (rows-1)/2) * square
y = (i - (cols-1)/2) * square
z = 0
```

### 2.2 为什么需要“角点归一化”

棋盘格中心对称，检测器可能从相反的角开始返回。实测同一张图：

- 经典检测器从 `P0` 开始，顺序为 `P0 → ... → 对角`；
- `findChessboardCornersSB` 常常从对角开始，顺序正好反过来。

如果不管，两个检测器算出的姿态会差 180°（绕 Z 轴），画面看起来“好像也对”，
但三色轴会翻转。代码在检测后检查 `P0` 周围四个方格：

- 取 `P0` 到 `P1` 的方向为 `u`，到 `P[cols]` 的方向为 `v`；
- 在 `P0 ± 0.45·square·u ± 0.45·square·v` 采四个 5×5 中值；
- 比较“主对角线”和“副对角线”的亮度和；
- 这块板的 `P0` 主对角线应为深色；若不符，把整个数组倒序。

这样经典检测器和 SB 的角点顺序统一，且 `P0` 始终跟随同一块物理角点。
对这块 10×7（一奇一偶）的板，黑白签名还能区分 180°；现场仍建议标题朝上。

## 3. 角点顺序的验证

### 3.1 代码里的可视化

结果图上：

- 所有内角点画绿色小圆；
- `P0` 画红色圆圈并标 `P0`；
- 坐标轴从棋盘中心画出。

### 3.2 旋转靶标检查

把靶标在板面内**顺时针转 90°**：

- 若角点是“图像顺序”，`P0` 会固定在图像左上；
- 若角点是“靶标自身顺序”，`P0` 会跟着物理角点走。

本代码采用后者。用 10×7 的合成板做过 0°/90°/180°/270° 四个方向的检查：
归一化后 `P0` 始终映射回同一块物理内角点。真实板因为 9×6 不是正方形，转 90°
后图案变成 9×6，OpenCV 仍能用 `(6,9)` 检出，但代码用“6 沿短边、9 沿长边”的
计数关系把 X/Y 绑在物理长/短边上，所以轴不会被转丢。

### 3.3 180° 歧义

棋盘格绕法线转 180° 后图案本身看起来一样。这块板是 10×7 格（一奇一偶），
角点周围的黑白签名在 180° 后会翻转；代码的归一化会利用它。现场让标题朝上即可，
不要故意把靶标倒过来考“能不能分”——纯棋盘格没有文字/图案时，180° 是原理性
歧义，必须靠不对称标记或固定摆放解决。

## 4. PnP 解算

### 4.1 3D-2D 对应

- 3D：54 个物点，单位米，全部在 `z=0` 平面；
- 2D：54 个图像角点，单位像素；
- 数量远大于 4，平面靶标也不缺约束。

### 4.2 为什么平面靶标 4 个点也能解 6-DoF

平面靶标满足单应：

```text
s · [u, v, 1]^T = K · [r1 r2 t] · [X, Y, 1]^T
```

单应矩阵 `H = K [r1 r2 t]` 有 8 个自由度；4 组点对应给出 8 个方程，正好解出 H。
已知 K 后：

```text
[r1 r2 t] = K^{-1} H
r3 = r1 × r2
```

再对 `[r1 r2 r3]` 做正交化，就得到 R 和 t（6-DoF）。方格边长固定了尺度，所以
平移的单位是米。

**多解风险**：平面靶标存在“镜像/双解”歧义——两个不同的姿态可以投影出同一组
角点，尤其在靶标接近正对、噪声较大或点很少时。用 4 个点风险最大；本代码用全部
54 个点，并用 IPPE 的双解 + 重投影误差筛选，风险小很多。

### 4.3 flag：`SOLVEPNP_IPPE`

选择 `cv2.SOLVEPNP_IPPE`（通过 `cv2.solvePnPGeneric` 调用），理由：

1. 靶标是**平面**，IPPE 专门为平面目标设计，利用单应分解，不需要初值；
2. 它直接给出平面位姿的**两个候选解**，正好对应上面说的多解风险；
3. 相比 `SOLVEPNP_ITERATIVE`，不依赖初值，不容易收敛到局部极小；
4. `SOLVEPNP_SQPNP` 是通用快速解，不暴露平面双解信息，不利于解释和筛选。

`SOLVEPNP_ITERATIVE` 作为 IPPE 完全失败时的兜底（正常不会走到）。

### 4.4 IPPE 双解怎么选

`solvePnPGeneric(..., flags=cv2.SOLVEPNP_IPPE)` 返回 2 组 `(rvec, tvec)`。
对每组计算重投影 RMSE：

```text
RMSE = sqrt( mean_k || project(K, dist, R, t, P_k) - p_k ||² )
```

取 RMSE 小的那组。示例（`img_01.jpg`，0.295 m）：

```text
solution 0: RMSE = 0.49 px   ← 选它
solution 1: RMSE = 12.48 px
```

两组误差通常相差一个数量级。若两组误差很接近（比如都很大或只差 0.1 px），
说明当前帧病态（角点噪声大、靶标接近侧视、点共线等），此时位姿不可信。
代码还会拒绝 `RMSE > 3 px` 的结果，宁可显示“未找到”，也不显示一个错误的姿态。

### 4.5 精化：`solvePnPRefineLM`

在 IPPE 选出的解上调用：

```python
rvec, tvec = cv2.solvePnPRefineLM(objp, imgp, K, dist, rvec, tvec)
```

它以重投影误差为目标做 Levenberg–Marquardt 迭代。代码只在精化后 RMSE **变小**
时采用新解，避免偶发发散。精化前角点已经由 `cornerSubPix` 做到亚像素；精化主要
让 54 个点的残差更均衡，对姿态是“小修正、提稳定性”，不会改变量级。

### 4.6 距离越远误差越大

针孔模型下，横向误差近似：

```text
δx ≈ z · δu / fx
```

同一像素误差 `δu`，距离 `z` 翻倍，横向误差也翻倍。

深度主要由靶标在图像中的**尺寸**决定。设靶标有效边长 `L`，图像上边长 `l ≈ f L / z`，
则

```text
z ≈ f L / l,    δz ≈ z² · δl / (f L)
```

即深度误差随 `z²` 增长；同时远处靶标只占更少像素，角点定位误差 `δl` 本身也会
变大，两者叠加。靶标倾斜、畸变、运动模糊都会进一步放大误差。这也是精度实验
要记录“每档 z 均值 ± 标准差 + 绝对误差”的原因。

## 5. 欧拉角

### 5.1 从 rvec 到 R

```python
R, _ = cv2.Rodrigues(rvec)
```

`R` 把物体系向量旋转到相机坐标系（物体系 → 相机）。

### 5.2 去掉“正对姿态”的 180°

因为物体系 Z 指向相机、相机 Z 向前，正对时 `R0 = diag(1, -1, -1)`，不是单位阵。
如果直接对 R 做欧拉分解，正对靶标会显示 180°，很容易让人以为符号错了。

代码先算相对偏差：

```text
Rdev = R · R0^T
```

正对时 `Rdev = I`，三个角都是 0。

### 5.3 旋转顺序

```text
Rdev = Ry(yaw) · Rx(pitch) · Rz(roll)
```

即**内旋 Y-X-Z**（等价于外旋 Z-X-Y）。提取公式：

```text
pitch = asin( -Rdev[1,2] )
yaw   = atan2( Rdev[0,2], Rdev[2,2] )
roll  = atan2( Rdev[1,0], Rdev[1,1] )
```

角度单位：度。范围：`roll, yaw ∈ (-180, 180]`，`pitch ∈ [-90, 90]`。

| 角 | 转轴 | 直观含义 |
| :-- | :-- | :-- |
| yaw（偏航） | 相机 Y 轴（竖直向下） | 靶标左右转，右边缘远离/靠近相机 |
| pitch（俯仰） | 相机 X 轴（水平向右） | 靶标上下俯仰，上边缘远离/靠近相机 |
| roll（横滚） | 相机 Z 轴（光轴向前） | 靶标在自身平面内旋转 |

符号按右手定则。正对、正立时三个角都应接近 0；现场转动时看数值是否跟着变、
方向是否一致即可。组合大角度时欧拉角有顺序依赖，报告里写清顺序就是为了避免
“同一姿态换一种顺序差很多”的追问。

**万向锁**：`pitch → ±90°` 时 yaw/roll 退化（只有组合有意义）。棋盘格接近侧视时
本来就检测不到，正常使用不会到 ±90°；代码不做特殊处理，报告里说明即可。

## 6. 可视化与实时性

### 6.1 坐标轴

`cv2.drawFrameAxes` 从物体系原点（棋盘中心）画：

- X 红、Y 绿、Z 蓝；
- 长度取长边内角点跨度的一半：`0.5 × (rows-1) × 17 mm = 68 mm`；
- Z 轴指向相机，透视上看起来“戳向自己”，这是正常的（题目也特别提醒过）。

### 6.2 信息叠显

第一行按题目要求的量：

```text
[dist: 1.234 m, yaw: +15.2 deg, pitch: -3.1 deg]
```

第二行补充：

```text
[roll: +2.3 deg, x: +0.123 m, y: -0.045 m, z: +0.987 m]
```

第三行：

```text
[reproj: 0.53 px, solutions: 2, detector: SB@0.4]
```

> 说明：OpenCV 自带的 Hershey 字体不含中文，窗口里用 `dist / yaw / pitch / roll`
> 英文标签，数值格式与题目要求一致；位姿计算与标签语言无关。若现场一定要中文，
> 可以用 PIL + 系统中文字体替换 `_draw_panel`，不影响 PnP 部分。

### 6.3 检测策略与 FPS

1080p 下 `findChessboardCornersSB` 全分辨率约 180 ms，达不到 15 FPS；
`findChessboardCorners` 全分辨率约 25–60 ms，也不够稳。最终采用：

1. **主路径**：SB 在 **0.4 倍**分辨率检测（约 768×432），角点乘回 1/0.4，
   再在**全分辨率**灰度图上做 `cornerSubPix`；
2. 失败：经典检测器 0.6 倍；
3. 图片模式再兜底：全分辨率经典 → 0.5 倍 SB → 全分辨率 SB；
4. 摄像头/视频只做前两步 + 0.5 倍 SB，避免单帧过慢。

在 M2-1 的 26 张标定图上实测（1920×1080，Python 3.10 / OpenCV 5.0）：

| 指标 | 值 |
| :-- | :-- |
| 检出率 | 26/26 |
| 单帧耗时（均值 / 中位数 / 最大） | **32.4 / 31.4 / 42.0 ms** |
| 处理帧率（均值 / 最差） | **30.9 / 23.8 FPS** |
| 重投影 RMSE 范围 | 0.32–0.84 px |

主路径 SB@0.4 与全分辨率经典检测的角点，经全分辨率 `cornerSubPix` 后逐点比较：
22 张两者都能检出的图，姿态差 0.00 mm / 0.00°（角点收敛到同一亚像素位置）。
因此 0.4 倍只是“找大致位置”，精度由全分辨率亚像素精化保证。

摄像头按 MJPG 1920×1080@15 打开，处理 30 FPS 余量足够；窗口右上角显示实测 FPS。

### 7.3 畸变的影响

做法：同一帧，分别用带畸变和不带畸变解 PnP；只改变 `dist`，角点和求解流程完全

## 8. 误差来源与现场注意事项

| 来源 | 影响 | 处理 |
| :-- | :-- | :-- |
| 方格边长没量准 | 距离整体按比例偏 | 卡尺量 17.0 mm；重打后用 `--square-mm` |
| 棋盘纸翘曲 | 平面 `z=0` 假设破坏，远处/边缘误差大 | 贴硬纸板，不要手持软纸 |
| 角点定位噪声 | 距离越远、倾斜越大越明显 | 用全分辨率 `cornerSubPix`，靶标占画面 1/3–2/3 |
| 自动对焦 | 焦距变化使内参失效 | 摄像头模式尝试关闭 AF；用固定焦距 |
| 分辨率不是 1920×1080 | 内参缩放只是近似 | 尽量用标定分辨率 |
| 运动模糊 | 角点拖影 | 手稳/支架，避免快速移动 |
| 强反光/阴影 | 角点检测失败或偏移 | 漫射光，避免灯直射棋盘纸 |
| 靶标接近侧视 | 平面双解退化，RMSE 变大 | 保持与光轴夹角别太大；代码拒绝 RMSE>3 px |

现场流程建议：

1. 确认 `--calib` 指向 M2-1 的 YAML，分辨率 1920×1080；
2. 标题朝上，靶标贴平，放在画面中间偏内；
3. 距离 0.3–1.2 m，靶标占画面约 1/3–2/3；
4. 看第三行 `reproj` 是否 < 1–2 px；若经常 > 2 px，先查光照/倾斜/对焦；
5. 用卷尺量相机到靶标中心，和 `dist` 对比，记录偏差；
6. 需要截图时按 `s`，结果在 `results/axis_*.png`。

## 9. 三个必答问题（速答版）

1. **为什么 4 个点也能解 6-DoF？有没有多解风险？**
   平面单应 8 个自由度，4 组对应给 8 个方程；已知 K 后分解出 R、t，方格尺寸定
   尺度。风险是平面靶标的双解/镜像歧义，点少、噪声大、接近正对时更明显；用全部
   54 个点 + IPPE 双解筛选可以压住。

2. **IPPE 为什么输出两个解？怎么选？**
   平面目标在同一组投影下可能对应两个不同姿态（一个“翻面”解）。用重投影 RMSE
   选小的；两组误差接近时说明病态，代码直接拒绝（RMSE > 3 px 也不输出）。

3. **为什么距离越远误差越大？**
   横向误差 `δx ≈ z·δu/f`，随 z 线性增长；深度误差 `δz ≈ z²·δl/(fL)`，随 z²
   增长，同时远处靶标占像素少、角点误差变大，两个效应叠加。
