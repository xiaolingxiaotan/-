## 1. 为什么检测器不够，非要加这一层

M2-3 的检测器每帧独立输出，**它不记得上一帧发生过什么**。这带来两个具体问题：

1. **框在抖**：同一本书逐帧的框中心有 1.5~3 px 的随机抖动（检测噪声）。
   直接把它当位置，速度估计就会来回跳，追踪 ID 在相邻目标间容易跳变。
2. **遮挡时没有输出**：目标被挡住的 5~10 帧里，检测器什么都不给。
   没有检测 → 没有可匹配的对象 → 轨迹被删 → 再出现时分配新 ID。

卡尔曼滤波同时解决这两件事：它用「预测 + 观测」的加权平均抑制抖动，
并且在没有观测时**继续用预测值输出**，让轨迹活下来。

## 2. 关联策略（题面 §2.1 的五问）

| 问题 | 本实现的选择 | 理由 |
| :-- | :-- | :-- |
| 匹配阈值 | IoU ≥ **0.3**（用**预测框**算，不是上一帧检测框） | 0.3 是"两个框至少重叠三成"的直觉线；用预测框是因为目标移动后，上一帧位置可能已经偏出去半个框 |
| 算法 | **匈牙利**（`scipy.optimize.linear_sum_assignment`） | 贪心在两目标交叉时会先到先得，锁错 ID；匈牙利是全局最优分配 |
| 新目标诞生 | 连续 **2 帧**命中才发 ID | 单帧偶发检测（背景误检）不给 ID，这就是"抖动检测会刷出假目标"的解法 |
| 老目标死亡 | 连续 **10 帧**无匹配才删 | 与遮挡预测上限一致，见 §4 |
| 置信度 | **两阶段**：先 ≥0.5 匹配，再用 0.15~0.5 补匹配 | 低分检测只允许匹配已有轨迹、不新建，避免背景噪声刷假目标 |
| 类别 | 类别不同**不匹配**（代价设 1e6） | 允许跨类匹配会让"杯子"抢走"保温杯"的轨迹 |

**ID 复用**：`Tracker._next_id` 只增不减，删除轨迹不回收 ID。
轨迹删除后即使原位置出现新目标，也拿新 ID——这是"ID 不复用"的实现保证。

## 3. 卡尔曼滤波（题面 §2.2 的 Q/R 依据）

状态量 `[cx, cy, vx, vy, w, h]`：中心 + 速度 + 宽高。宽高也进状态，
因为同一个物体的框宽高会在 ±5 px 内抖动，只平滑中心的话框会"呼吸"。

**R（观测噪声）必须有实测来源**，不能拍脑袋。做法：

```python
# 取一段静止目标的连续 50 帧检测框
R = [var(cx), var(cy), var(w), var(h)]
```

在合成序列的静止目标上实测：`var(cx) ≈ 0.9`、`var(cy) ≈ 1.0`、
`var(w) ≈ 2.5`、`var(h) ≈ 2.3`（合成数据加了 σ=1.5px 的高斯抖动）。
函数 `kalman.measure_jitter()` 就是这段逻辑，换成真实视频的静止片段直接可得。

**Q（过程噪声）的量级依据**：按加速度假设，位置噪声 ≈ `a·dt²/2`、
速度噪声 ≈ `a·dt`。目标在画面里的典型加速度按「1 秒内速度变化 2 倍框宽」估，
即 `a ≈ 2·w`（像素/帧²），本实现取 `q_accel = 2.0`。
真实视频里应改成用真实加速度分布拟合，做法见 §6。

**为什么不用匀速直线外推**：外推只给点估计，无法表达"这一步有多可信"。
卡尔曼维护协方差 P，遮挡越久 P 越大，才能做 §4 的误差曲线和
"第几帧开始不可信"的定量判断。

## 4. 遮挡与预测（题面 §2.3）

规则：未匹配到检测时**不删**，用预测值继续输出、画**虚线框**并标 `PREDICTED`，
连续预测 **≤10 帧**；超过 10 帧删除。重新匹配上时用新检测更新、**ID 不变**、虚线恢复实线。

### 4.1 遮挡恢复率（合成序列，3 个在画面内的目标取平均）

| 遮挡帧数 | 纯 IoU | + 卡尔曼 |
| :-- | :-- | :-- |
| 5 | **0%** | **100%** |
| 10 | **0%** | **67%** |
| 15 | 0% | 0% |
| 20 | 0% | 0% |

纯 IoU 全是 0%，因为它的轨迹在无检测时立即删除（`max_age=0`），
这正是题面 §0 说的「遮挡时没有检测可用，目标就被删了」。
10 帧那档掉到 67%，是因为其中一个目标和另一个在空间上靠得过近，
第 11 帧恢复时被错误关联——这是当前实现已知的弱点（见 §6）。

### 4.2 预测误差曲线：10 帧阈值的依据

把 `max_age` 放开到 30、让预测一直跑到 25 帧，误差（预测中心 vs 参考中心）随帧数的变化：

| 帧数 | 1 | 3 | 5 | 10 | 15 | 20 | 25 |
| :-- | :-- | :-- | :-- | :-- | :-- | :-- | :-- |
| 误差 (px) | 1.8 | 6.2 | 9.7 | **16.8** | **25.8** | 31.4 | 63.9 |

曲线见 `results/occlusion_curve.png`。

**阈值定 10 帧的依据**：目标框短边约 70 px，误差到 16.8 px（24% 短边）时
框还"盖得住"目标；到 25.8 px（37%）时已经盖不住，视觉上会明显错位。
所以 **10 帧是"预测还可用"的上限**，不是照抄题面。

5 帧会怎样：能更早放弃，但遮挡 6~8 帧的常见场景就会丢 ID；
20 帧会怎样：多撑 10 帧的代价是那段框已经飘到 30 px 外，
追踪器会带着这个错位置去和别的目标抢匹配，反而拉高错跟率。
**这就是「保持率」与「错跟率」的权衡。**

## 5. 与纯 IoU 的对比（题面 §2.5 的证据链）

| 指标 | 纯 IoU | + 卡尔曼 | 变化 |
| :-- | :-- | :-- | :-- |
| ID 总数 | 6 | 6 | 相同 |
| ID 切换次数 | 0 | 0 | 相同 |
| 遮挡 5 帧后 ID 保持率 | 0% | **100%** | +100pp |
| 遮挡 10 帧后 ID 保持率 | 0% | **67%** | +67pp |
| 静止目标抖动（相邻帧中心位移 std） | 0.978 px | **0.696 px** | **-29%** |

合成序列比较干净，所以「ID 切换」两边都是 0——**这个指标要在真实视频的
交叉场景上才有区分度**（合成的交叉是匀速直线，IoU 关联不会错）。
抖动 -29% 是卡尔曼平滑的直接证据，这个在真实视频上会同样成立。

## 6. 已知不足与改进方向

1. **交叉场景的 ID 互锁**：当前只靠 IoU + 类别，两目标交叠时可能交换。
   改进：把卡尔曼的**预测位置**也加进代价（已用预测框做 IoU，但可以进一步
   加入速度方向一致性项），或用外观特征（本任务物料种类少，外观区分度低，
   优先级不高）。
2. **R 现在是合成数据的方差**，真实视频要用 `measure_jitter()` 重测；
   如果检测器在不同光照下抖动不同，应按类别分别给 R。
3. **遮挡期间不做"预测可信度"可视化**：卡尔曼的 P 已经在算（`Track.pos_std()`），
   可以按标准差给虚线框做透明度渐变，这是题面 §2.4 的可选进阶项。
4. **CTRV 转弯模型**（可选进阶）未实现：本任务物料多为平移，CV 够用；
   若做车载场景应换成恒转弯率模型。
